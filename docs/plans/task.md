# 任务定义：红利低波50ETF（515450）温度计逆向择时策略的长程智能体工作流

> 课程：金融人工智能编程 · 期末作业
> 状态：v2 已定稿（2026-11-08 复核通过）

## 1. 背景、用户与现状

- **任务**：为"波段交易 515450 并迭代改进策略"这一需重复执行的研究循环，
  设计端到端长程智能体工作流：提出假设 → 取数 → 回测 → 评审 → 修订 → 再回测，
  直至通过验收标准。
- **目标用户/读者**：课程评审（任课老师/助教）。评审重点是工作流设计本身——
  阶段划分、状态持久化、as_of 纪律、中断恢复、可重复评估是否完整可信；
  金融结论合理即可。工作流同时保留本人长期复用价值。
- **现状**：该研究循环此前停留在纸面思考，无成体系回测与迭代记录，
  工作流需把全流程从零固化。

## 2. 策略定义

- **标的**：红利低波50ETF（sh515450，南方基金），2020-01-17 上市；
  低波动、均值回复特征强、有定期分红（除息跳空需用复权价处理）。
- **信号源**：自制"红利低波50温度计"择时指标（估值+热度+拥挤度合成，日度，
  取值 [0,100]，2018-01-02 ~ 2026-08-12，2087 个交易日，无缺失无重复）。
  文件：`data/raw/红利低波50ETF择时信号.xlsx`（列：DateTime、温度计总值）。
- **主假设（v1，已定稿）**：单阈值二元择时
  - 判定：t 日收盘后用 t 日温度计总值判定；
  - **> 85 → 全部清仓**：t+1 日清仓，仓位归 0；
  - **≤ 85 → 满仓**：t+1 日满仓持有或再入场，仓位 100%；
  - **不设现金保留、不分档建仓**；
  - 回测起点（上市日）当日温度计 ≤85，则立即满仓入场。
- **信号频率自查（已复核）**：回测区间内温度计 >85 的上穿/下穿各 5 次，
  合计约 10 次交易（另计起点入场 1 次），贴近验收标准第 4 条（≥10 次）的下限。
- **对照假设**：布林带均值回复 + 200 日均线趋势过滤（原主假设，降级为对照，
  用于评审阶段的横向参照，不参与迭代）。
- **基线**：买入持有（全程满仓，后复权口径）。
- **分红处理**：信号与回测统一使用**后复权价**（hfq）；另保留不复权价
  用于除息日附近异常校验。

## 3. 回测设定

- **区间**：信号覆盖期与 ETF 上市以来的交集。起点 = ETF 上市日
  （取数阶段用行情数据自动确认，不写死，记录于 run 元数据）；
  终点 = min(信号末日, 行情末日)，首轮 as_of = 2026-08-12，约 6.6 年。
  信号文件更新后工作流自动延长窗口并记录 as_of 变更。
- **成本**：佣金单边万 3、买卖双边；免最低 5 元；ETF 无印花税；无滑点
  （报告中注明此局限）。
- **资金与仓位**：初始资金 100 万元；仓位为二元状态——满仓 100% 或清仓 0%，
  无现金缓冲，满仓期间不存在闲置资金收益。

## 4. 工作流阶段与触发

六个阶段，每阶段独立落盘、可单独重跑：

```
① 提出假设 → ② 取数(as_of校验) → ③ 回测执行 → ④ 自动评审(指标+基线对比)
     ↑                                                    ↓
     └──────── ⑥ 修订(调参/改结构) ←── ⑤ 评审门槛(裁决记录) ──┘
```

- 每次迭代 = 一个 `run`：含假设版本、参数快照、数据快照哈希、全部指标、
  评审结论、是否通过验收。
- **触发事件**：(a) 手动触发新迭代（主）；(b) 验收未通过自动进入修订
  （最大迭代次数上限 **5 次**，防死循环）；(c) 新数据到达触发当前最优策略复核。
- **中断恢复**：run 从最后一个完整阶段继续；历史 run 全部可重放、可对比。

## 5. 阶段输入、数据源与 as_of 纪律

| 阶段 | 输入 | 数据源 | as_of 要求 |
|---|---|---|---|
| ① 假设 | 上一 run 评审结论 | 本地 | 不涉数据 |
| ② 取数 | 信号 xlsx；ETF 后复权日线 | akshare（主源）+ 本地缓存快照（原始 CSV + 哈希 + 截至日） | 行情截至日 ≤ 信号截至日；终点 = min(两者, 用户 as_of) |
| ③ 回测 | ② 的数据快照 | 本地 | 严格用快照，禁止回测中联网取数 |
| ④ 自动评审 | ③ 的净值与交易明细 | 本地 | 指标口径与基线一致 |
| ⑤ 评审门槛 | ④ 的指标表 | 本地 | 裁决理由落盘 |
| ⑥ 修订 | ⑤ 的裁决 | 本地 | 生成下一假设版本 |

## 6. 交付物、验收标准与修订策略

- **交付物**：
  - `runs/` 状态库：每次 run 的假设快照、数据哈希、指标、评审结论（可复现可恢复）；
  - `docs/` 迭代日志：逐轮假设→结果→裁决的演变记录；
  - 验收裁决记录：每次评审门槛的通过/否决及理由，单独成档；
  - 最终 A4 研究备忘 PDF（latex 技能模板）：策略描述、回测结果、基线对比、
    迭代历程、局限。
- **验收标准（对照买入持有基线，全部满足才算通过）**：
  1. 策略年化收益 ≥ 基线年化 × 1.05；
  2. 最大回撤 ≤ 基线最大回撤 × 0.7；
  3. 夏普比率 ≥ 基线夏普 × 1.2；
  4. 交易次数 ≥ 10（排除偶然性）；
  5. 稳健性：阈值 ±5 时验收结论不反转。
- **修订策略（预案顺序）**：
  1. v1 阈值 85。若交易次数不足 10 或稳健性不达标，
     **首要预案：阈值降至 80**（回测区间上穿/下穿各 9 次，约 18 次交易，
     信号频率显著改善，已复核）；
  2. 其次：引入信号确认延迟 N 日（解决边界抖动，与滞回带思路二选一）；
  3. 再次：修改规则结构（如分档仓位、双阈值滞回带）；
  4. 每轮修订必须基于 ⑤ 的裁决记录说明动机，禁止无理由改参；
  5. 达到最大迭代次数仍不通过，则如实输出未通过结论与原因，不强行凑标准。

## 7. 为什么需要持久化工作流而非一次性脚本

1. **状态跨多次迭代演化**：策略研究是"假设→证据→新假设"的链条，
   每次修订依赖前序 run 的结论与数据快照；一次性脚本无法回答
   "第 3 版假设相对第 1 版改了什么、数据是否变了"。
2. **可重复评估**：同一 run 可用同一数据快照哈希重放，指标可复现；
   历史 run 横向对比是"迭代改进"的证明。
3. **as_of 纪律**：信号与行情有各自的截至日，且会更新；
   持久化记录每次取数的 as_of 与快照哈希，杜绝静默使用未来数据。
4. **中断恢复**：长程运行可能在中途失败（网络、数据缺口、评审否决）；
   阶段化落盘使恢复从最后一个完整阶段开始，而非从零重来。
5. **审计与评分**：课程评审需要看到决策链条（为何修订、否决理由），
   状态库 + 裁决记录提供完整审计轨迹。
